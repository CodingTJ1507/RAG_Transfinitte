HTTP Status Codes: 4xx Reference

Published 2025-11-20. General reference.

400 Bad Request

The server could not parse the request, for example invalid JSON.

401 Unauthorized

The request has no valid credentials. The client should send or refresh its credentials. This status is about authentication, not about the request body.

403 Forbidden

The client is known but is not allowed to do this action.

409 Conflict

The request conflicts with the current state, for example a reused idempotency key with a different body.

422 Unprocessable Content

The body was parsed but failed validation, for example a required field is missing. Older documents call this status "Unprocessable Entity".

Application error codes are not HTTP statuses

Many APIs return their own codes such as "ABC-401". The number inside such a code is chosen by the API owner and does not have to match an HTTP status. Always check the HTTP status line and the API's own error table.
