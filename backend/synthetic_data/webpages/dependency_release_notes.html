schemaguard 3.0 Release Notes

Published 2026-09-15. Applies to schemaguard 3.0.0 and 3.0.1.

Overview

schemaguard is a JSON request-validation library. Version 3.0 is a major release with breaking changes. Read this page before upgrading from 2.x.

Breaking Changes in 3.0.0

Field aliases are now opt-in. In 2.x, aliases declared in a schema were always resolved. In 3.0, the setting allow_aliases defaults to false. Aliases are ignored unless you set allow_aliases: true in the validator config.

Unknown fields. Fields not defined in the schema are ignored and reported in the error message as "unrecognized field ... ignored". An ignored alias does not count as its target field, so a required target field will be reported as missing.

Error messages. Validation errors now list every failing field.

Python. Python 3.10 or newer is required.

Migrating from 2.x

If any of your clients still send aliased field names, add allow_aliases: true to your validator config before upgrading, or move those clients to the new names first.

3.0.1 (2026-09-29)

Bug fix: date-time fields with a trailing "Z" were rejected on some platforms. No behaviour changes to aliases.
